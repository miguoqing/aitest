## 怎么用这本手册

先看测试点**长什么样**，再挑方法。方法是工具，不是清单任务——硬凑十种方法只会产出十条重复用例。

挑方法看两个信号：这个测试点的**证据里有什么类型的约束**（数字、开关、角色、状态），以及**失败会长什么样**（算错、被绕过、卡住、串数据）。这两个信号基本决定了该用哪两三种方法。

选完写进 `methods.applicable`，不适用写进 `methods.skipped` 并给原因。第四级只对 `applicable` 里的方法负责：标了适用却没产出用例，校验脚本会告警。

## 逐点过筛

以"打卡范围 100 至 300 米"这个测试点为例：

```yaml
methods:
  applicable: [边界值法, 错误推测法, 等价类划分]
  skipped:
    - method: 并发法
      reason: 距离校验是无状态纯函数，无共享写入
    - method: 状态迁移法
      reason: 无状态机
```

过筛的产出不是"用十种方法"，而是**两三个真正能产出不同用例的方法**。边界值法产出 99/100/300/301 米四个点；错误推测法产出"关闭定位权限后能否打卡""模拟定位能否绕过"；等价类划分产出"规则含两个地点时，坐标分别落在各地点范围内/外"。三条用例验的是三件事，不是同一件事的三种说法。

不适用要写原因，而且原因要**可反驳**。"不适用"不可反驳，"无共享可变状态"可反驳——审阅者能拿去检验。

## 十二种方法

### 边界值法

**触发**：证据里有数值、时间窗、数量上限、距离区间。

**写法**：取每个阈值的下界-1、下界、上界、上界+1，以及恰好命中。区间型（100–300 米）四个点；上限型（人数上限）取 `上限-1 / 上限 / 上限+1`。

**产出示例**：定位距办公地点 99 米不可打卡、100 米可打卡、300 米可打卡、301 米不可打卡。

**坑**：只测区间内不测刚出界，等于没测边界。另外注意文档写"100 至 300 米"是闭区间还是开区间——没写清就标 `pending_confirmation`，别自己定。

### 等价类划分

**触发**：输入可以切成互斥的类，同类行为应一致。

**写法**：列出有效类与无效类，每类取一个代表值，并**记录为什么这类只取一个**。类别来源通常是：范围内/外、某部门/某成员/白名单、状态分类。

**产出示例**：打卡人员选部门、选成员、两者混合、白名单成员——四类各一条。

**坑**：把"有效类"写成"正常情况"一条了事。等价类划分的价值在于**证明你考虑了哪些类**，所以类要列全。

### 错误推测法

**触发**：有安全敏感点、有权限边界、有文档留白、有非常规入口。

**写法**：从"怎么才能让它出错"倒推。常用问句：能不能绕过这个入口？能不能改包？能不能用别人的身份？能不能让两个约束互相矛盾？文档没写的地方会不会正好是漏洞？

**产出示例**：非规则内成员直接访问打卡接口、规则已保存后成员被移出部门、超出管辖范围的分级管理员构造请求修改规则。

**坑**：这条方法最容易产出"合理但无据"的用例。凡是断言了文档没写的行为，必须降级为 `pending_confirmation`。错误推测法的正确用法是**提出一个好问题**，不是**给出一个预期结果**。

### 穷举法

**触发**：组合空间小且必须全覆盖——通常是 2–3 个开关的有限组合。

**写法**：列出全部组合（`2^n`），逐条给预期。组合数超过 8 个就换成判定表法或正交裁剪，并说明裁剪依据。

**产出示例**：拍照打卡开关 × 备注仅拍照开关的 4 种组合，各自验证缺照片/相册来源是否被拦。

**坑**：不设上限的穷举会爆。爆了不是用例多，是设计没做完。

### 逆向场景法

**触发**：每条正向主链路都要配一条反向。

**写法**：把正向用例的每一步逐条反过来问"这一步不做/做错会怎样"。

**产出示例**：正向是"审批通过后异常状态校准为正常"；逆向是"审批被拒后状态保持异常"和"审批通过但时段不匹配，状态保持不变"。

**坑**：逆向场景不等于异常输入。逆向是**从结果倒推哪一步可以被破坏**，比"输入非法字符"更有杀伤力。

### 因果图法

**触发**：多个条件与结果之间是组合逻辑，判定表的行数已经不好手工推。

**写法**：列出原因（条件）与结果，画因果连线，标注或/且/非与互斥约束，转成判定表再转用例。

**产出示例**：可见范围（全员/指定部门）× 打卡应用入口权限 × 管理员身份，三者的组合决定入口是否可见。

**坑**：两三个条件的简单与或关系用判定表足够，上因果图是过度设计。真的缠绕（有互斥约束、有中间节点）才用。

### 场景法

**触发**：需要验端到端可用，或一条业务主线跨多个功能点。

**写法**：写"前置 → 触发 → 主链路 → 结果"，一条用例串完整条业务流。跨功能点的场景法用例是唯一能发现"每个功能单独都对、串起来不对"的方法。

**产出示例**：创建规则 → 绑定成员 → 员工打卡 → 产生异常 → 提交补卡 → 审批通过 → 状态校准，全链路。

**坑**：场景法用例最容易变成"什么都验一点"，导致一条用例多个目标。串链路时明确**本用例只判定终点那一个状态**，中间步骤的判定交给各自的用例。

### 异常法

**触发**：有外部依赖、有网络、有文件、有用户输入。

**写法**：非法输入、缺失依赖、超时、断网、服务不可用、脏数据、并发写冲突。每类取一个真实会发生的情形，不要编科幻场景。

**产出示例**：U 盘导入时考勤机导出的文件列缺失、考勤机离线时打卡记录无法实时同步。

**坑**：把"系统崩溃"当异常用例。不可控且不可复现的场景没有回归价值。

### 并发法

**触发**：同一数据会被多方同时改写，或操作可重复提交。

**写法**：两个操作同时作用于同一对象；重复提交（双击、刷新、返回再提交）；审批与打卡同时发生。

**产出示例**：同一员工在补卡审批通过与请假审批通过同时发生时，校准状态以哪条为准；重复提交补卡申请是否产生两条单据。

**坑**：并发用例必须写清**时序**和**期望的仲裁结果**。只写"并发打卡"无法执行。仲裁结果文档没写的，标待确认。

### 安全性法

**触发**：有权限分级、有防作弊、有敏感数据、有数据导出。

**写法**：越权（水平/垂直）、绕过（改包、直接调接口、隐藏入口）、防作弊（截图、模拟定位、相册代拍）、数据泄露（导出范围超出可见范围）。

**产出示例**：分级管理员构造范围外部门的导出请求；开启"只能拍照"后通过相册选择图片；非可见范围成员直接访问打卡接口。

**坑**：安全用例的断言要写**具体被拒绝的表现**（403、无数据、入口不存在），不能只写"应当失败"。

### 判定表法

**触发**：2–4 个开关/条件组合决定结果，组合可以用表格穷举。

**写法**：条件列在左，动作列在上，逐行给组合与预期。表格本身就是用例来源，一列条件组合一条用例。

**产出示例**：「员工异常打卡可提交申请」开关 × 审批结果 × 时段是否匹配，三条件组合决定校准结果。

**坑**：条件一多表就爆（4 个条件 = 16 行）。超过 4 个条件时改用正交裁剪，并**写明裁剪了哪些组合、为什么可裁**。

### 状态迁移法

**触发**：有明确状态机：待审批 → 通过/驳回 → 校准。

**写法**：列出状态与合法迁移，每个迁移一条用例，外加非法迁移（跳步、重复触发、逆向迁移）。

**产出示例**：补卡申请从"待审批"直接到"已校准"（跳过审批）；审批通过后又驳回；同一单据重复审批。

**坑**：只测合法迁移不测非法迁移。跳步和重复触发恰恰是状态机最容易出 bug 的地方。

## 组合与取舍

一个测试点通常配 2–4 种方法。常见的有效组合：

| 测试点特征 | 主力方法 | 补一位 |
| --- | --- | --- |
| 有数值阈值 | 边界值法 | 错误推测法（模拟定位、改包） |
| 多开关组合 | 判定表法 / 穷举法 | 逆向场景法 |
| 有状态机 | 状态迁移法 | 并发法（重复提交） |
| 有权限分级 | 安全性法 | 等价类划分（各类角色） |
| 纯展示/文案 | 场景法 | — 通常 S4，不必上重方法 |

方法取舍的理由要写进 `methods.skipped`。这是给审阅者看的，也是给自己下一轮复查看的。

## 常见误用

| 误用 | 后果 | 改法 |
| --- | --- | --- |
| 每条都写"等价类划分" | 方法分析变成形式主义，边界和越权全漏 | 按证据类型重新过筛 |
| 一个测试点只产出一条用例 | 覆盖不足，等于只验 happy path | 每个适用方法至少一条 |
| 一条用例套用三种方法 | 目标不单一，失败无法定位 | 拆成三条，一条一个主方法 |
| 用方法名当测试点 | "边界值分析测试"不是测试点 | 测试点要写成可判定的断言 |
| 错误推测法编造预期 | 无据断言，评审信任崩塌 | 降级为 `pending_confirmation` |
