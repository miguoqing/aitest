# 学生档案管理系统 — 系统概述

## Overview

学生档案管理系统是面向院校教务人员、辅导员、档案管理员的轻量化数字化档案管理平台，用于替代传统纸质档案的登记、流转、归档与查阅模式。系统以学生基础学籍信息为关联主体，完成学籍档案、奖惩档案、学籍变动档案、毕业档案的全生命周期管理，要求全程数据留痕、流程标准化、格式统一化，保障档案数据真实、完整、安全、可溯源。

## 文档定位

该需求规格说明书是项目研发与验收的基线文档，明确定义：

- 系统界面规范
- 业务单据流程
- 数据流转逻辑
- 数据库数据结构
- 统一数据格式标准

文档主张自身可作为产品设计、开发编码、功能测试、项目验收的**唯一依据**。对测试工作而言，这意味着功能验收用例应逐条对齐文档中的界面字段、单据规则、状态锁定与数据格式约束，而不是另立标准。

## 目标用户与业务背景

| 维度 | 内容 |
|------|------|
| 目标用户 | 院校教务人员、辅导员、档案管理员 |
| 系统定位 | 轻量化数字化档案管理平台 |
| 替代对象 | 传统纸质档案的登记、流转、归档、查阅 |

## 功能范围

系统核心业务分为两大模块：

1. **学生信息管理模块** — 学生基础学籍信息的录入、校验、维护与批量管理。
2. **学生档案管理模块** — 四类档案的全生命周期管理：学籍档案、奖惩档案、学籍变动档案、毕业档案。

两大模块之外，系统提供一组通用能力：数据查询、批量导入导出、操作日志溯源、数据权限控制、表单校验、状态锁定。文档强调"无自定义模糊操作"，所有行为可溯源、可审计。

## 范围之外

明确不纳入本期的内容：服务器硬件部署、第三方接口拓展、多系统对接等拓展性需求。

同时文档提出可拓展性要求：数据结构预留拓展空间，支持后续新增档案类型、新增学生信息字段、拓展权限角色。

## 术语约定

| 术语 | 含义 |
|------|------|
| 学生基础信息 | 学生身份、学籍、联系方式等静态基础数据，是档案数据的核心关联主体 |
| 学生档案 | 包含学籍档案、奖惩档案、学籍变动档案、毕业档案在内的全维度学生资料，支持文字内容与附件材料 |
| 档案单据 | 档案新增、编辑、删除、归档、查阅、导出对应的业务操作凭证，全局唯一、操作留痕 |
| 数据流 | 前端页面、后端服务、文件服务器、数据库之间的数据提交、校验、传输、存储及更新逻辑 |

## 非功能需求

| 属性 | 要求 |
|------|------|
| 数据一致性 | 学生信息与档案关联数据同步更新，无数据冗余、无数据冲突、无数据失联 |
| 数据安全性 | 已归档数据锁定保护，所有操作全程日志溯源，杜绝非法篡改、恶意删除 |
| 易用性 | 界面统一规范，操作流程简单标准化，表单校验提示清晰无歧义，降低人工操作失误率 |
| 可拓展性 | 数据结构预留拓展空间，支持后续新增档案类型、学生信息字段、权限角色 |

其中"数据安全性"在业务层落地为一条硬规则：已归档档案禁止编辑与删除，且操作日志独立存储、永久留存（详见 [业务单据与流程设计](business-workflows.md)）。
