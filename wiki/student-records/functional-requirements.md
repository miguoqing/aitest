## Overview

功能需求按两大模块展开，每条都是可直接转化为验收条件的无歧义定义。核心约束有三条：学号与身份证号永久锁定；仅「未归档」档案可编辑；存在已归档档案的学生不得删除。其余功能围绕新增、查询、导出与溯源展开。

## 学生信息管理功能

| 功能 | 需求定义 |
|------|----------|
| 信息新增 | 支持单条手动新增与 Excel 批量导入新增；系统自动校验学号、身份证号重复数据，重复数据拦截并提示 |
| 信息编辑 | 仅允许修改姓名、联系电话、年级班级、学籍状态等可编辑字段；学号、身份证号永久锁定，任何场景不可修改 |
| 信息查询 | 支持多条件组合精准查询、模糊查询，支持空条件查询全部数据，查询结果实时渲染 |
| 信息导出 | 支持单条、批量导出 Excel 文件，包含全部基础字段，格式标准化 |
| 信息删除 | 无已归档档案的学生数据可正常删除；存在已归档档案的学生数据禁止删除，避免档案数据失联断层 |

## 学生档案管理功能

| 功能 | 需求定义 |
|------|----------|
| 档案新增 | 必须关联指定学生账号，选择标准档案类型，填写规范档案内容，支持多份附件上传 |
| 档案编辑 | 仅「未归档」状态档案支持编辑修改；「已归档」档案永久锁定，禁止任何编辑、替换、删除操作 |
| 档案归档 | 支持单条归档、批量归档；归档前自动校验数据完整性，归档后数据永久留存锁定 |
| 档案查询 | 支持按学生信息、档案类型、归档状态、时间范围多维度组合筛选，查询精准无遗漏 |
| 档案导出预览 | 支持在线预览附件文件、批量导出 PDF/Excel 档案资料，用于存档、上报 |
| 档案溯源 | 档案全生命周期操作全程留痕，可随时查看完整操作日志与流转记录，满足审计要求 |

## 测试关注的不变量

以下规则在多个章节反复出现，构成系统的核心不变量，适合作为优先覆盖的回归点：

1. **标识锁定** — 学号、身份证号、档案编号一经生成即不可修改（任何角色、任何入口）。
2. **归档即冻结** — 状态从「未归档」变为「已归档」后，编辑、删除、附件替换全部失效，仅保留查看与导出。
3. **级联删除边界** — 删除学生只清理未归档临时档案；存在已归档档案时整体阻断删除。
4. **全操作留痕** — 新增、编辑、删除、归档、导出、查询均产生可审计日志，包括操作人、时间、内容与客户端 IP。
5. **格式强校验** — 学号 10 位纯数字、身份证 18 位（小写 x 归一为大写 X）、手机号 11 位纯数字，任何不合规输入必须被拦截。
