## 1. 文档说明

### 1.1 范围

本套用例覆盖打卡模块的管理侧配置与考勤侧判定，共 15 个功能点：规则类型与统计口径、打卡人员与白名单、打卡方式、打卡地点与范围、上下班时间与容差、外出打卡、拍照打卡、补卡申请、特殊日期打卡、打卡提醒、应用可见范围、审批关联与智能校准、分级管理权限、记录查看与导出、API 导出数据。

### 1.2 依据与边界

| 项 | 说明 |
| --- | --- |

#### TC-ATT-001 创建「固定时间上下班」规则，员工按相同时间打卡并被统一判定

| 项 | 内容 |
| --- | --- |
| 功能点 | 规则类型与统计口径 |
| 测试场景 | 打卡规则创建 |
| 测试点 | 固定时间上下班规则的创建与统一时间判定 |
| 测试用例 | 创建「固定时间上下班」规则，员工按相同时间打卡并被统一判定 |
| 设计方法 | 场景法 |
| 关键标签 | 冒烟, 正向 |
| 严重等级 | S2 严重 |
| 前置条件 | 管理员已登录管理后台并具备打卡规则配置权限；企业通讯录中已有部门与成员 |

**测试步骤**

1. 进入【管理后台】>【企业应用】>【打卡】>【上下班打卡】>【设置】>【添加规则】
2. 规则类型选择「固定时间上下班」，打卡人员选择测试部门
3. 打卡方式选择「手机打卡」，添加上班/下班时间并保存规则
4. 让该部门员工在设定时间区间内完成上下班打卡
5. 前往【查看】查看该员工当日打卡记录与状态

**预期结果（测试结果）**

- 规则保存成功，规则类型显示为「固定时间上下班」
- 同部门员工使用同一套上下班时间判定，状态按正常/迟到/早退输出
- 打卡记录可在【上下班打卡】>【查看】中查询到

**原始文档上下文**

> 固定时间上下班：员工按照相同时间打卡，适合办公时间固定的上班族。
>
> —— `wiki/attendance-management/attendance-rule-configuration.md`

| 项 | 内容 |

| 设计方法 | 场景法 |
| 关键标签 | 正向 |
| 严重等级 | S2 严重 |
| 前置条件 | 管理员具备规则配置权限；已存在早班、晚班两套排班 |

**测试步骤**

1. 进入【添加规则】，规则类型选择「按班次上下班」
2. 打卡人员选择分早晚班的测试部门，配置打卡方式与打卡地点
3. 保存规则并分别给早班、晚班员工排班
4. 早班员工在早班时段打卡，晚班员工在晚班时段打卡

| 5 | 打卡范围的配置取值区间 | TC-ATT-014 | 文档给出「100至300米」有效区间，但未说明后台是否允许配置区间外的半径值。 |
| 6 | 同一时段多类型审批并存 | TC-ATT-037 | 文档列出五种审批模板可参与校准，未定义同一时段存在多张不同类型通过单据时的匹配优先级。 |

### 4.6 结论

1. 三篇文档的 15 个业务功能点均已建立用例，文档明确写出的 20 条可测试判定点中，18 条完全覆盖、1 条部分覆盖，判定点覆盖率 92.5%。
2. 用例以正向主链路 + 异常/边界成对覆盖：正向 27 条、异常 15 条、边界 7 条，避免只有正向用例导致缺陷漏出。
3. 高风险面集中在四处：自由上下班的统计口径、手机打卡的「或」判定、审批校准的数据准确性、分级管理员的越权访问，共 7 条 S1 用例（TC-ATT-003、TC-ATT-008、TC-ATT-009、TC-ATT-028、TC-ATT-038、TC-ATT-039、TC-ATT-043），建议列入冒烟与回归必跑集。
4. 共有 6 项文档未定义的行为，已登记为待确认项；确认结论前，相关用例的预期结果不作为缺陷判定依据。
